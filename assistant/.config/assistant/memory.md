## 2026-08-27 — Model identity + panel/child behavior

What model I run on is a runtime choice: check panel footer, then ~/.local/state/quickshell/ori-model.json, then PI_MODEL/PI_PROVIDER; a change applies only on next cold spawn. Panel commands are panel-owned (/model /effort /new /compact /name /export /restart — /restart kills the pi child, never the broker). Shift+Tab cycles effort (arrives as Key_Backtab); effort heat colors via panel.effortColor(); feedback must go to `notice`, anything in `error` pins the border. Debug via `qs -p ~/.config/quickshell log` (-f/-t/--rules) AND qmllint — QML errors are visible there, not invisible. Warm pi re-reads nothing (skills/commands refresh only on cold spawn, ~10-min idle kill); a stale command menu is preferred over a wrong one. set_thinking_level acks anything — trust only get_state or the event. Effort scale: off/minimal/low/medium/high/xhigh.

## 2026-08-30 — Panel scroll/selection internals

BTT ListView: newest message at contentY == -height, oldest at -contentHeight; both collapse to -height when content fits. A Flickable with content smaller than viewport stops delivering wheel events to children — wheel faces must be siblings. An anchored item as a direct child of a Column silently breaks the positioner — anchor inside the field instead. Touchpad wheel = pixelDelta at event rate: apply 1:1, no animation, no notch quantising. Harness: /usr/lib/qt6/bin/qmltestrunner -platform offscreen -input <file>; console.* prints as QDEBUG. Selection: Selection.qml singleton (registered TextEdits, anchor+head) + SelectableArea; unregistered items are skipped in copies by construction.
